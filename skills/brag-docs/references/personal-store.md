# Personal store

Use when **Store owner** is `personal`. The entry must stay useful after the user leaves the company and safe to hold outside it.

## Generalize before preview

Rewrite each draft so no confidential detail reaches the store:

| Specific (keep out) | General (write instead) |
|---|---|
| Customer or partner name | "a top-5 enterprise customer", "a retail client" |
| Internal codename or system name | "internal billing platform" |
| Internal URL, ticket link | "ticket in billing backlog, Mar 2026" |
| Revenue, cost, financial figures | Relative change: "cut cloud spend noticeably", or a percentage the user says is public |
| Unreleased product details | "upcoming payments feature" |
| Security incident specifics | "resolved a Sev-2 security issue" |
| Code, credentials, schemas | Omit |

Keep what belongs to the user: what they did, their role, the size of the change, dates, public links.

In preview, list what was generalized ("customer name → 'enterprise customer'") so the user can check nothing important was lost.

Done when every draft in preview reads safely outside the company.
